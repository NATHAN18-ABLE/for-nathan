# 개인 PR 포트폴리오 사이트 — 설계 문서

작성일: 2026-10-22 · 상태: 사용자 최종 승인 대기

## 1. 의도 (왜 만드는가)

AI 영상·VFX 스튜디오 채용 담당자와 대표에게 "나"를 소개하는 사이트.
지원 시점은 2026년 말 ~ 2027년 초 (확정 마감 없음).

담당자가 보고 나서 남아야 할 인상:
1. "AI를 마술처럼 다루는데, 그걸로 실제 업무를 해내는 사람이구나"
2. "신뢰가 가고, 더 궁금하다"

포지셔닝: AI 기술자가 아니라 **AI를 언어로 삼는 미디어 감독**. 중심은 언제나 사람의 이야기.

담당자의 실제 행동 가정: 사이트 전체에 1~3분, 작품 하나에 2~3분. 대부분은 끝까지 스크롤하지 않는다.
그래서 작품을 빠르게 보여주고, "사람(나)이 한 일과 AI가 한 일"을 분명히 구분해 보여주는 것이 핵심이다.

## 1-1. 최우선 원칙: 미감 (사용자 강조)

> "촌스럽거나 AI 티 나지 않게. 정말 미감이 있다는 것, 이 사람이 세련됐다는 것이 보여야 한다.
> 디자인뿐 아니라 단어와 말, 색도 중요하다."

이 원칙은 모든 단계의 합격 기준이다.

- **말**: 과장 형용사·업계 상투어를 쓰지 않는다 (예: 혁신적인, 열정 가득한, 시너지, 무한한 가능성, 새로운 지평, 압도적인 / elevate, unleash, seamless, cutting-edge, passionate). 짧고 구체적인 문장, 숫자와 고유명사로 말한다. 한국어는 존댓말 평서문으로 담백하게. 영어는 직역이 아니라 같은 태도의 영어로 다시 쓴다. 확정 카피는 바꾸지 않되, 다듬을 제안은 따로 목록으로 올려 사용자 승인 후 반영한다.
- **색**: 먹색 바탕은 단색 한 장이 아니라 미세한 층(바탕/면/선)으로 깊이를 낸다. 금색은 면적 5% 이하, 얇은 선·작은 기호·핵심 단어에만 쓴다. 금색 그라데이션·광택 효과·네온 글로우·보라/파랑 AI 그라데이션은 쓰지 않는다.
- **디자인**: 여백이 주인공. 장식보다 비례와 타이포. 카드 그리드·아이콘 나열·이모지 같은 템플릿 패턴 금지. 이펙트는 정해진 네 순간에만.
- **차분함** (사용자 강조: "과도하게 정신없고 어지러운 느낌 지양, 채용담당자 입장에서 꼭 봐야 함"): 한 화면에 움직이는 것은 하나만. 스크롤을 빼앗는 연출(강제 스냅, 긴 고정 구간 연속) 금지. 3D 기울기·패럴랙스는 작은 폭으로만. 모든 연출은 2초 안에 끝나고 반복하지 않는다. 담당자가 원하는 정보(작품, 연락처, 이력서)까지 클릭 두 번 이내.
- **검수**: 단계마다 스크린샷을 보고 "이게 세련돼 보이는가", "담당자가 피곤하지 않은가"를 먼저 묻는다. `hallmark audit`으로 AI 슬롭 패턴을 점검한다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 영상 6편이 각기 다른 제작 방식이라는 점을 보여줘 "어떤 의뢰든 맞는 방법을 고르는 사람"으로 읽히게 한다.
- 작품마다 제작 과정과 "문제와 결정"을 보여줘 프롬프트만 넣은 사람이 아님을 증명한다.
- 사용자가 코드를 몰라도 `content.js`만 고쳐 문구·작품·링크를 교체할 수 있다.
- 한국어/영어 두 언어 지원.
- 데스크톱과 모바일 모두에서 부드럽고 읽기 쉽다.

**비목표**
- 블로그, 관리자 페이지, 로그인.
- 첫 버전의 Supabase 연동 (아래 결정 9 참조).
- 서양 마술사 클리셰(모자, 지팡이, 토끼).

**실패 조건 (작동해도 실패)**
- 이펙트가 화려해서 글이 안 읽힌다 — 겹친 글씨, 작고 어두운 글씨.
- 템플릿 같은 "AI가 만든 사이트" 느낌.
- 빈 placeholder가 그대로 노출되어 미완성으로 보인다. (placeholder는 개발 중에는 눈에 띄게, 배포 전에는 반드시 교체하거나 숨긴다.)
- 모바일에서 히어로가 버벅이거나 데이터를 과하게 먹는다.
- 담당자가 작품을 찾지 못하고 나간다.

## 3. 제약

- 사용자: 바이브 코더, Windows 노트북. 쉬운 용어로 설명하고 단계마다 확인받는다.
- 배포: HTML/CSS/JS → GitHub(NATHAN18-ABLE) → Netlify. 이전 프로젝트와 같은 흐름.
- 주소: 첫 버전은 무료 `<서브도메인>.netlify.app`. 서브도메인 이름은 첫 공유 전에 확정한다 (링크 미리보기는 절대 주소가 필요하고, 카카오톡이 미리보기를 오래 캐시하기 때문). 개인 도메인은 나중에 필요하면 추가.
- 사이트는 **새 저장소**에 둔다. 현재 `for-nathan`은 스킬 모음 저장소이므로 섞지 않는다. 이 설계 문서만 여기 둔다.
- 텍스트·작품 데이터는 레이아웃 코드와 분리(`content.js`).
- 아직 없는 영상·사진·링크는 눈에 띄는 placeholder + 교체 위치 주석.
- 컬러: 바탕 `#080808` / 본문 `#f2ede5` / 보조 텍스트 `#b0a99f` 이상 밝기 / 포인트 금색 `#c8a96e`.
- 폰트: 본문 Pretendard, 제목 두께감 있는 한글 세리프(Noto Serif KR 600~900). 본문 최소 16px, 웨이트 400 이상.
- 정렬 (2026-10-22 사용자 결정): **최대한 전부 중앙 정렬.** 좌측 정렬은 문장이 어색하게 잘려 보이므로 쓰지 않는다. 대신 본문 줄 길이를 짧게(약 30em) 두고, 문장 단위로 줄을 나누며, 한글은 단어 중간에서 줄이 바뀌지 않게(`word-break: keep-all`) 한다.
- 제목 글꼴 확정: **Noto Serif KR**(한글) + **Noto Serif Display**(영문). 본문 Pretendard.

## 4. 구현 방식 (Approaches)

### 4-1. 사이트 제작 방식

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A. 순수 HTML/CSS/JS + GSAP (선택)** | 빌드 도구 없음. GSAP는 CDN으로 불러옴 | 이전 배포 흐름 그대로, 설치 없음, 파일 열면 바로 보임 | 이미지 최적화는 스크립트로 따로 처리 |
| B. Vite 등 빌드 도구 | npm 빌드 후 배포 | 이미지 최적화·페이지 관리 자동 | Node 설치, `npm run dev`, Netlify 빌드 설정 필요 |
| C. React / Next.js | 컴포넌트 기반 웹앱 | 대규모 확장에 유리 | 이 사이트엔 과함, 직접 수정 어려움 |

**선택: A.** 이유: 사용자가 익숙한 배포 흐름을 그대로 쓰고, 파일을 직접 열어 고칠 수 있다.

### 4-2. 히어로 스크롤 영상

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **① 이미지 시퀀스 + canvas (선택)** | 영상을 WebP 프레임으로 쪼개 스크롤 진행도에 맞춰 canvas에 그림 | 가장 부드러움, iOS 안정적 | 파일 수 많음(PC 8~12MB) |
| ② `<video>` currentTime 스크러빙 | 영상 파일 하나를 스크롤에 맞춰 이동 | 간단 | 일반 인코딩은 끊김, 전 프레임 키프레임으로 바꾸면 용량 커짐, iOS Safari 버벅임 |

**선택: ①.** 이유: 애플 제품 페이지와 같은 부드러움이 컨셉의 핵심이고, 모바일 안정성이 가장 높다.

## 4-3. 컨셉 확정: 「트릭 공개」 + 「낙관」

- **트릭 공개**: 마술사는 트릭을 숨기지만 이 사람은 공개한다. 작품마다 마술(완성 영상) → 트릭 공개(제작 과정) 순서.
- **크레딧 형식**: 트릭 공개는 영화 엔딩 크레딧처럼 "역할 | 누가"를 가운데 정렬로 적는다. 사람이 한 줄에는 이름과 금 낙관(人), AI가 한 줄에는 도구 이름(Kling · Seedance 등)을 적는다. 영상 업계 사람은 크레딧을 바로 읽으므로 설명 없이도 의도가 전달된다. 마지막에 한 줄 안내: "도장이 찍힌 줄은 제가 직접 한 일입니다."
- **금색은 낙관에만**. 버튼·선·테두리·장식에는 쓰지 않는다.
- AI 티를 빼는 규칙: 대문자+자간 넓힌 라벨, 기능 소개식 칸 나눔 그리드, 금색 밑줄, 동그란 재생 버튼 같은 템플릿 장치를 쓰지 않는다.

## 5. 결정된 내용

### 5-1. 페이지 흐름 (원래 12개 → 10개)

공연 흐름: 오프닝 → 마술사 소개 → 트릭 → 피날레

1. **Hero** — 스크롤 영상 (오프닝). 고정 구간은 화면 약 2장 길이로 짧게, "작품 보기 ↓" 버튼으로 작품까지 바로 이동 가능 (담당자가 작품을 못 찾고 나가는 일 방지)
2. **About** — 마술사 소개
3. **AI 영상** — 대표작 크게 + 나머지 카드 → 상세 페이지
4. **AI 이미지 & 사운드** — 묶음 갤러리 + 제작 과정
5. **실전 기록** — 탭 3개: 마케팅 / 개인 프로젝트 / 현장 경험 (이름은 임시)
6. **Toolkit** — 한 줄 띠로 짧게
7. **Why Me** — 카드 3장 ♠ ♦ ♣
8. **Philosophy**
9. **Finale**
10. **Contact** — ♥ 네 번째 카드

마케팅·개인 프로젝트·현장 경험을 하나로 묶은 이유: AI 영상 스튜디오 담당자는 작품 섹션에서 대부분의 시간을 쓴다. 이 셋은 "일을 끝까지 해내는 사람"이라는 신뢰의 근거로 짧고 굵게 보여준다. (사용자가 판단을 위임함)

### 5-2. 네비게이션 (5개)

AI 영상 / AI 이미지 / 실전 기록 / Why Me / Contact
+ 우측: KO/EN 전환, 이력서 PDF 버튼

### 5-3. AI 영상 라인업 (6편)

| 작품 | 방식 태그 | 보여주는 능력 | 상태 |
|---|---|---|---|
| 17분 (가제) | 종합 · 시네마틱 | 여러 기법을 엮어 영화를 만드는 연출력 | 준비 중 — **대표작 후보** |
| TOXIC | 스타터 프레임 | 프레임 설계, 캐릭터 일관성 (Kling/Seedance, 캐릭터 레퍼런스) | 완성, 약 25초 16:9 네오누아르 |
| Just Leave | 연기 연출 | 행동·대사 디테일 프롬프팅으로 끌어낸 연기 | 완성 |
| 자동차 광고 | Blender 프리비즈 | 구도·카메라 워킹을 먼저 설계 | 제작 중 |
| 넾다세일 출품작 | 애니메이션 · 상업 | 광고 문법 + 애니메이션 (네이버 '넾다세일 AI 광고제' 출품 예정) | 제작 중 |
| 추가 1편 | 미정 | — | 미정 |

- 카드에는 장르보다 **방식 태그**를 크게 붙인다.
- 대표작은 `content.js`의 `featured: true` 한 줄로 바꾼다. 17분 완성 전까지는 TOXIC을 대표작으로 둔다.
- 제작 중 작품은 "제작 중" 표시를 정직하게 달고, 기획서·스타터 프레임·Blender 프리비즈를 먼저 보여준다.
- 영상은 YouTube(일부 공개) 또는 Vimeo에 올려 임베드한다. Netlify 무료 전송량 보호와 회사망 재생 안정성 때문.

### 5-4. 작품 상세 페이지 (`work.html?id=<작품id>`)

담당자 질문 3가지에 답하는 구조: 무엇을 만들었나 / 사람이 한 일과 AI가 한 일 / 우리 팀에서도 통할까.

1. 한 줄 요약 + 메타: 역할, 기간, 사용 툴, 길이, 상태
2. 완성 영상 (제작 중이면 티저·프리비즈)
3. **문제와 결정** 2~3개 — 부딪힌 문제와 내가 고른 해결법 (사용자가 나중에 작성, 지금은 placeholder)
4. 제작 과정 — 크레딧 형식(4-3)으로 "역할 | 누가"를 적고, 단계별 이미지 1~2장을 곁들인다
5. 한 장면 들여다보기 — 프롬프트 원문 / 생성 결과 / 최종 편집본 나란히
6. 이전·다음 작품 이동

### 5-5. 한/영 이중 언어

- `content.js`의 모든 문구는 `{ ko: "...", en: "..." }` 형태.
- 우측 상단 KO/EN 토글. 선택은 브라우저에 기억(localStorage, 실패해도 한국어로 정상 동작).
- 영어 문구는 Claude가 초안 작성 → 사용자 확인.
- 영어 히어로 메인 카피는 직역하지 않는다 (링컨 게티즈버그 연설로 읽힘). 별도 문장 제안 예정.

### 5-6. 추가 결정 (사용자 승인한 아이디어 9가지)

1. 영어 히어로 카피는 별도 문장.
2. **Finale 검은 화면 반사**: 피날레 영상이 끝나면 2초간 완전한 검정 → 모니터에 보는 사람의 얼굴이 실제로 비침 → 문구 등장. 웹캠은 쓰지 않는다. 문구 초안: "이 화면에 비친 당신처럼, 저도 처음의 설렘으로 왔습니다." (확정 전)
3. About 자격: 운전면허는 작게 또는 제외, 드론 자격증은 Toolkit/현장 경험 쪽으로 이동.
4. **이력서 PDF 다운로드** 버튼 — 네비 + Contact.
5. **60초 쇼릴** 버튼 — 히어로 바로 아래. 쇼릴 영상은 placeholder.
6. **링크 미리보기 이미지(OG 이미지)** — 카카오톡·메일 공유용, 별도 디자인.
7. **♥ 네 번째 카드** — Contact에서 사용자가 직접 뒤집는 카드. 뒤집으면 "사람·온도" 메시지와 연락 버튼이 드러남. "선택은 당신의 몫입니다"를 실제 동작으로.
8. **나우 유 씨 미 이펙트는 한 곳에 하나씩**:
   - 카드 펼침 → Why Me
   - 비가 멈추는 순간 → Philosophy (금빛 입자가 떨어지다 문장이 나타날 때 공중에서 정지)
   - 폭죽 → Finale
   - 연기 → 히어로/섹션 전환에 아주 옅게만
9. **Supabase는 첫 버전에서 제외**. 문의 폼은 Netlify Forms. 나중에 작품 클릭 통계 등이 필요해지면 그때 추가.

### 5-7. 인터랙션 원칙

- 커스텀 커서: 금색 점 + 따라오는 링. 터치 기기에서는 끔.
- 섹션 reveal: 스크롤 시 부드럽게 등장.
- 3D 스크롤 / 마우스 트래킹: 카드·대표작 썸네일 정도에만, 과하지 않게.
- `prefers-reduced-motion`이면 모든 연출을 정지 화면/즉시 표시로 대체.
- 이펙트는 글씨 위에 겹치지 않는다. 텍스트 대비는 항상 우선.

## 7. 히어로 스크롤 영상 상세

- 원본: 힉스필드 스타트/엔드 프레임 기반 영상 (아직 없음 → 임시 영상/그라데이션 프레임으로 placeholder).
- 프레임 추출: ffmpeg로 120~180장, PC 1600px 폭 WebP(품질 ~70), 모바일 800px 폭 별도 세트.
- 동작: 히어로 구간을 약 200vh 길이로 고정(pin)하고, 스크롤 진행도 0→1에 따라 프레임 번호를 계산해 canvas에 그림. GSAP ScrollTrigger 사용.
- 로딩: 첫 프레임 즉시 표시 → 8장 간격 프레임 먼저 로드 → 나머지 채움. 로딩 중에도 스크롤 가능.
- 카피(라벨/메인/부제/서브/버튼)는 영상 위에 겹치지 않도록 구간을 나눠 등장하거나, 충분한 어둠 그라데이션 위에 배치.
- 얼굴 삽입 여지: 영상 교체만으로 가능하도록 프레임 폴더 구조를 고정.
- reduced-motion: 마지막 프레임 정지 이미지만 표시.
