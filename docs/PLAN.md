# Seoul, printed for you: 나와 닮은 서울의 구를 찾아주는 여행 사이트 계획서

> 서울관광재단을 대상으로 한 개선 제안 프로젝트(발표용 고완성 프로토타입). 공식 사이트가 아니며 재단 로고·브랜딩은 사용하지 않는다.

## 1. 문제와 목표

- **문제**: 기존 서울관광재단 홈페이지·앱은 관광 정보를 나열형으로 제공한다. 여행자가 자신에게 맞는 곳을 직접 찾아야 하고, 결국 누구나 아는 몇 곳에 몰린다.
- **목표**: 외국인이 MBTI처럼 간단한 성향 테스트로 **서울 12개 구 중 나와 닮은 구**를 찾고, 그 구에서 한국을 깊게 체험할 수 있는 장소와 식당으로 짠 **하루 코스**를 순서대로 받는다. 같은 구를 고른 사람끼리는 **메타버스**에서 만난다.
- **차별점**: 유명 명소 목록 대신 동네(구) 단위 매칭. 시장, 골목, 공방, 노포, 산책길처럼 생활이 보이는 곳을 고른다.

대상 구 12곳: 강남구, 종로구, 마포구, 용산구, 송파구, 노원구, 영등포구, 중구, 관악구, 성동구, 서대문구, 동대문구

## 2. 사용자 흐름

1. **첫 화면**: 목판에 새긴 서울 지도. 12개 구가 각각 따로 새긴 판목 조각으로 맞물려 있다. "Find my Seoul" 한 번으로 테스트 시작
2. **성향 테스트 (약 2분)**: 상황형 2지선다 12문항. 답할 때마다 지도 조각에 먹이 묻어 가며 어느 구에 가까워지는지 은근히 보인다
3. **결과: 나의 여행 유형 + 나의 구**: 4글자 유형 코드와 이름, 매칭된 구와 그 이유, 차선 구 1곳. 결과 카드는 이미지로 저장·공유
4. **하루 코스**: 아침 → 점심 → 오후 → 간식·카페 → 저녁 → 밤. 각 지점마다 왜 깊은 경험인지, 이용 팁(주문법, 예절), 다음 지점까지 이동 방법
5. **메타버스 입장**: 메타버스가 있는 구라면 "같은 구 여행자 만나기"로 바로 입장. 없는 구라면 성향이 가장 가까운 구의 방을 안내

## 3. 성향 테스트 설계

### 4개 축 → 16가지 여행 유형

| 축 | 한쪽 | 다른 쪽 |
|---|---|---|
| 시간의 결 | **H** Heritage: 오래된 것, 노포, 손으로 만든 것 | **T** Trend: 새로 생긴 것, 디자인, 실험 |
| 무대 | **A** Alley: 골목, 시장, 실내 | **O** Open: 산, 강, 공원, 성곽길 |
| 분위기 | **C** Calm: 조용히, 혼자, 관찰 | **B** Buzz: 북적임, 사람, 밤 |
| 속도 | **L** Linger: 한 곳에 오래 | **F** Flow: 여러 곳을 빠르게 |

- 유형 코드 예: `HACL` "The Alley Scholar", `TOBF` "The River Runner". 16개 유형마다 이름과 한 줄 설명을 붙인다
- 문항 예: "Your first morning in Seoul?" A: "A quiet alley with an old tea house" / B: "A riverside run at sunrise"
- **12문항 전부 성향 문항**이다. 문항마다 1~2개 축에 점수를 주고, 4개 축이 각각 최소 2문항에서 점수를 받도록 배분한다
- 코스에 필요한 조건(음식 모험 정도, 걷기 vs 지하철)은 따로 묻지 않고 12문항 중 2문항의 답에서 함께 읽는다
- 한 축이 동점이면 그 축에 지정한 결정 문항의 답으로 정한다
- **문항 추가를 염두에 둔 구조**: 문항은 데이터 파일(문항, 선택지, 축별 가중치)로 관리하고 축 점수는 문항 수로 정규화한다. 문항을 늘려도 코드와 구 성향값은 바꾸지 않는다
- "MBTI"는 설명용 비유로만 쓰고 사이트 이름·유형 이름에는 쓰지 않는다(상표)

### 구 매칭

- 구마다 4개 축 성향값(-2 ~ +2)을 정의하고, 응답 점수와 가장 가까운 구를 1순위, 다음을 차선으로 고른다
- 결과 화면에서 "You lean Heritage and Alley, and Jongno is the most Heritage-and-Alley district on this map"처럼 축으로 이유를 설명
- **테스트로 검증**: 16개 유형 각각의 결과를 계산해 12개 구가 모두 1순위로 한 번 이상 나오는지, 한 구에 몰리지 않는지 단위 테스트로 확인

### 구 성향 초안 (데이터 단계에서 조정)

문항 12개, 실제 성향값(-2~+2), 16개 유형 이름, 분포 검증 결과는 [`docs/QUIZ.md`](QUIZ.md)와 `src/lib/match/`에 있다.

| 구 | 시간의 결 | 무대 | 분위기 | 속도 | 한 줄 성격 |
|---|---|---|---|---|---|
| 종로구 | H | A | C | L | 한옥 골목과 공방, 오래 머무는 동네 |

## 4. 구별 콘텐츠와 하루 코스

### 선정 기준

- **깊은 곳**: 그 동네 사람들의 생활이 보이는 시장, 골목, 공방, 노포, 산책길, 동네 사찰, 작은 박물관
- **과도하게 유명한 곳은 중심에서 뺀다**: 경복궁, 명동, N서울타워, 롯데월드 같은 대표 명소는 코스의 주인공이 아니라 "근처에 있다면" 정도로만 언급
- **식당**: 오래 운영된 노포, 시장 식당, 먹자골목을 우선한다. 개별 식당은 데이터 단계에서 영업 여부를 웹으로 확인하고 확인 날짜를 남긴다. 평점·순위는 만들지 않는다

### 코스 구성 방식

- 구마다 장소·식당 8~10곳(총 100~120곳)을 시간대 슬롯(아침, 점심, 오후, 간식, 저녁, 밤)에 배치할 수 있게 태그한다
- 사용자의 유형으로 슬롯마다 한 곳을 고른다: **L**이면 지점을 줄이고 머무는 시간을 늘리고, **F**면 지점을 늘리고, **B**면 밤 슬롯을 넣는다
- 지점 사이 이동은 좌표로 계산한 도보 시간과 가까운 지하철역·노선으로 안내
- 지점마다: 영어 이름, 한글, 로마자, 왜 깊은 경험인지 한 줄, 이용 팁, 운영 요약(확인 날짜 표기)

## 5. 정보 구조

| 경로 | 내용 |
|---|---|
| `/` | 목판 서울 지도 첫 화면 + 테스트 시작 + 12개 구 소개 |
| `/test` | 성향 테스트 12문항 |
| `/type/[code]` | 여행 유형 결과(공유 가능한 주소) + 매칭된 구 + 차선 구 |
| `/gu/[slug]` | 구 소개 + 유형에 맞춘 하루 코스 |
| `/gu/[slug]/visit` | 그 구의 메타버스 방 (5개 구만) |
| `/about` | 제안 배경, 데이터 출처·확인 날짜, 사진 출처, 생성 이미지 표기 |

- 다국어: `/[locale]` 세그먼트, 영어 기본 + 한국어 토글
- 결과 공유: 유형 코드와 구를 주소에 담아 링크 공유, 결과 카드 이미지는 코드로 생성(Satori). 최근 결과는 브라우저에 저장(서버 없음)

## 6. 디자인 방향: 백자와 서울의 빛 (2026-11-09 확정)

변경 이력: 목판 지도첩 시안 3장 탈락(어둡고 무거움, 생기 없음, 각진 버튼과 글자) → 민화 검토(만화처럼 보일 우려로 보류) → **백자와 서울의 빛** 확정. 사용자 요청은 "서울의 세련됨과 고급스러운 느낌"이다.

| 요소 | 사이트에서의 역할 |
|---|---|
| 달항아리의 흰 여백과 둥근 곡선 | 바탕과 여백, 둥근 버튼과 카드 모양 |
| 청화(백자에 푸른 안료로 그린 그림) | 지도, 코스 경로, 선 그림을 코발트 선으로 |
| 청자 비색 | 아주 옅은 보조 바탕색 |
| 해 질 무렵의 실제 서울 사진 | 생기와 현대적 세련됨, 구마다 대표 사진 |
| 고급 향수 브랜드의 "나에게 맞는 향 찾기" | 테스트 진행 방식: 한 문항씩 우아하게, 사진이 있는 선택지 |

- **색**: 백자 흰색 바탕, 먹색 글자, 청화 코발트 포인트 하나, 청자색은 옅은 바탕에만. 검정·금색, 베이지·놋색은 쓰지 않는다
- **형태**: 둥근 알약 버튼, 크게 둥근 카드(28px), 굵은 선과 각진 모서리 없음
- **글자**: 날렵하고 우아한 현대 산세리프. 고전적인 대비 강한 세리프는 쓰지 않는다
- **다이얼**: 비대칭 6 / 모션 6 / 정보 밀도 3 (고급스러운 절제에 맞춰 조금 낮춤)
- **대표 장면 "글레이즈"**: 결과가 나오면 코발트 선이 붓으로 그리듯 내 구의 윤곽과 하루 코스를 지점마다 그리고, 그 뒤로 구의 사진이 서서히 드러난다(코드 모션)
- **유형 결과 카드**: 캐릭터 없이 유형 이름, 코발트 선 그림, 구 사진으로 구성
- **메타버스와의 연결**: 메타버스는 아늑한 디오라마를 유지하되 백자 흰색, 청자색, 코발트로 색을 맞춘다

## 7. 메타버스: 같은 구 여행자끼리 만나기

### 방을 만들 5개 구 (확정, 추가 가능)

장면이 서로 겹치지 않도록 골목, 시장, 강변, 공장, 언덕을 하나씩 고른다.

| 구 | 장면 | 체험 |
|---|---|---|
| 종로구 | 서순라길 한옥 골목과 종묘 돌담 | 공방 들여다보기, 평상에 앉기, 한복 갈아입기 |
| 동대문구 | 경동시장 약령시 | 약재 가게 골목, 시장 식당에서 음식 받기 |
| 마포구 | 망원시장에서 망원 한강공원까지 | 시장 간식 들고 강변 피크닉, 노을 |
| 성동구 | 성수동 붉은 벽돌 공장 골목 | 수제화 공방, 루프탑 |
| 용산구 | 해방촌 언덕 계단길 | 계단 골목 오르기, 루프탑에서 남산 전망 |

나머지 7개 구가 결과로 나온 사람에게는 성향이 가장 가까운 방을 안내한다. 현재 계산 결과(`src/lib/metaverse/queue.ts`):

| 방이 없는 구 | 안내되는 방 |
|---|---|
| 중구 | 동대문구 |
| 서대문구, 노원구, 송파구 | 종로구 |
| 영등포구 | 마포구 |
| 관악구 | 용산구 |
| 강남구 | 성동구 |

5개 방이 모두 골목·시장형이라 산·공원형 구(서대문, 노원, 송파)가 종로로 모인다. 방을 추가한다면 산·공원형 구(예: 노원 경춘선숲길, 서대문 안산자락길)가 1순위 후보다.

**방 추가를 염두에 둔 구조**: 방 하나는 "장면 설정 파일(배치할 건물·소품 목록, 안내 지점, 시작 위치, 하늘색과 빛)" + 공통 엔진(이동, 아바타, 동기화, 대기열, 프리셋 소통)으로 나눈다. 새 구의 방은 설정 파일과 그 구에만 있는 소품만 만들면 추가되고, "가장 가까운 방 안내"도 방 목록에서 자동으로 다시 계산된다.

### 만남의 방식

- 방은 구마다 하나, **동시 10명**, 넘치면 순번이 보이는 대기열
- 아바타 머리 위에 여행 유형 코드 배지가 보인다. 같은 유형끼리는 작은 표시로 알아볼 수 있다
- 소통은 다국어 프리셋 문구("Hello!", "What's your type?", "Follow me", "Photo here?")와 이모트(인사, 손 흔들기, 사진 포즈)
- 단체 사진 지점: 모인 사람들이 함께 사진을 찍으면 화면 캡처 이미지로 저장
- 입장 조건은 두지 않는다(누구나 입장 가능). 결과를 가진 사람은 배지가 붙어 "같은 구 여행자"임이 보인다

### 표현과 기술 (기존 계획 유지)

- 아늑한 장난감 디오라마: 둥글고 통통한 저폴리곤, 큰 머리 아바타(한복·여행자 옷), 백자 흰색·청자색·코발트로 맞춘 색, 밝은 햇살. 생활 시뮬레이션 장르의 느낌만 가져오고 특정 게임의 캐릭터·그림체·UI·효과음은 쓰지 않는다
- 건물·소품·아바타 모두 코드로 만든다(React Three Fiber). 방마다 3D 자산 5MB 이내, 클릭할 때만 불러온다
- 동기화: 구별 Supabase Realtime 채널, 입장 시각 순 정렬로 10명 판정, Broadcast로 초당 10회 위치 전송
- 조작: 데스크톱 WASD·클릭 이동, 모바일 가상 조이스틱. WebGL이 안 되면 글·사진 대체 페이지
- 한계: 클라이언트끼리 합의하는 방식이라 조작된 클라이언트는 인원 제한을 피할 수 있다. 발표용으로 충분하고, 운영 단계에서는 서버가 인원을 강제하는 방식으로 교체

## 8. 이미지·영상 자산

**원칙**: Higgsfield 크레딧은 쓰지 않는다. 코드로 그릴 수 있는 것은 전부 코드로 만들고, 코드로 대신할 수 없는 이미지만 사용자가 직접 준비한다. 목록과 프롬프트는 [`docs/ASSETS.md`](ASSETS.md).

| 자산 | 준비 |
|---|---|
| 첫 화면 시안 3장 (백자와 서울의 빛) | 사용자, GPT 이미지 (지금) |
| 히어로 이미지(달항아리 정물 등) | 사용자, GPT 이미지, 시안 승인 후 1~2장 |
| 시안 속 질감·입체 부분의 고해상도 이미지 | 사용자, GPT 이미지, 시안 승인 후 필요할 때만 (예상 0~2장) |
| 장소 사진 | 사용자, 공공누리 공개 사진. 데이터 단계에서 목록 확정 후 |
| 서울 12개 구 목판 지도, 유형 결과 카드, 코스 경로, 전환 모션, 메타버스 전체 | 코드 |

## 10. 실행 단계

| 단계 | 할 일 | 스킬 |
|---|---|---|
| 0. 맥락·방향 (완료, 새 방향 반영) | 제품 정의, 디자인 방향, 다이얼, 라이브러리 | `impeccable`, `design-taste-frontend`, `ui-ux-pro-max`, `pick-ui-library` |
| 1. 시안 | 사용자가 GPT로 첫 화면 시안 3장 제작 → 1안 승인 | `impeccable` visualize |
| 2. 데이터·로직 | 12개 구 성향값, 문항 12개, 16개 유형 이름, 장소·식당 100~120곳 조사와 확인, 매칭·코스 엔진 테스트 작성 | `writing-plans`, `test-driven-development`, `karpathy-guidelines` |
| 3. 구현 | 첫 화면 → 테스트 → 결과 → 구 코스 → 공유 카드 | `impeccable` craft-floor, `emil-design-eng`, `apple-design` |
| 4. 메타버스 | Supabase 구성 → 대기열 로직 테스트 → 공통 엔진 + 방 1곳(종로) 완성 → 설정 파일로 나머지 4곳 → 동시 접속 검증 | `test-driven-development`, `apple-design`, `mobile-native` |
| 5. 모바일 | 화면 높이, 입력 확대, 노치 영역 | `mobile-native` |
| 6. 모션 | 필요한 곳만 골라 애니메이션 | `find-animation-opportunities` → `animate` |
| 7. 검수 | 접근성·성능, AI 디자인 흔적 점검, 모션 리뷰, 최종 다듬기, DESIGN.md | `impeccable` audit/polish, `hallmark audit`, `web-design-guidelines`, `review-animations`, `improve-animations` |

메타버스는 방 1곳을 먼저 끝까지 완성한 뒤 같은 틀로 나머지 4곳을 만든다. 일정이 빠듯하면 3곳(종로, 마포, 성동)으로 줄일 수 있다.
