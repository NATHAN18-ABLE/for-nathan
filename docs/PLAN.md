# Seoul, printed for you: 개인 맞춤형 서울 관광 사이트 계획서

> 서울관광재단을 대상으로 한 개선 제안 프로젝트(발표용 고완성 프로토타입). 공식 사이트가 아니며 재단 로고·브랜딩은 사용하지 않는다.

## 1. 문제와 목표

- **문제**: 기존 서울관광재단 홈페이지·앱은 관광 정보를 나열형으로 제공한다. 여행자의 관심사·목적·선호 활동을 반영한 추천이 없어 외국인이 자신에게 맞는 곳을 직접 찾아야 한다.
- **목표**: 외국인이 몇 분 안에 취향과 조건을 입력하고, **이유가 붙은 추천 장소**와 **걸어서 실행 가능한 하루 코스**를 받아 저장·공유할 수 있게 한다.
- **차별점**: 한국 전통 디자인을 표면 장식(오방색·단청 문양)이 아니라 **정보 구조와 인터랙션 자체**로 쓴다.

## 2. 디자인 방향 (확정)

**Design Read**: 외국인 개인 여행자를 위한 몰입형 인터랙티브 관광 경험. 한국 고지도 목판의 재질 언어, Next.js + Tailwind v4 + Motion/GSAP + 맞춤 타이포그래피.

**다이얼**: `DESIGN_VARIANCE 7 / MOTION_INTENSITY 7 / VISUAL_DENSITY 3`
(관광·브랜드 경험이라 비대칭·모션은 높게, 외국인 첫 방문자를 고려해 밀도는 낮게)

### 비주얼 월드: 목판 지도첩 (Woodblock Atlas)

김정호의 **수선전도**(1840년대 한양 목판 지도)와 **대동여지도**(1861, 22첩 접이식 목판 지도)의 문법을 여행자 한 사람을 위한 지도로 다시 새긴다.

| 지도첩 원리 | 사이트에서의 역할 |
|---|---|
| 목판(먹을 먹은 판목) | 기본 배경 재질. 새겨진 서울 = 아직 취향이 반영되지 않은 상태 |
| 한지에 찍어낸 인쇄본 | 개인화된 결과. 취향을 고르면 "나만의 서울"이 찍혀 나온다 |
| 지도표(범례) | 취향 선택 칩. 궁궐·시장음식·K컬처·산과 물·야경 등을 범례 기호로 |
| 10리마다 찍은 도로 눈금 | 코스 경로 위 도보 시간 눈금 |
| 절첩식(아코디언) 22첩 | 결과·일정 페이지가 접혔다 펼쳐지는 구조 |

- **색**: 먹(목판) + 차가운 한지 흰색 + **쪽빛(천연 인디고) 단일 포인트**. 크림색 종이 + 붉은 낙관 조합은 AI 디자인의 상투형이라 쓰지 않는다.
- **형태**: 카드 대신 새김 테두리, 둥근 모서리 대신 판각의 직선. 모서리 체계는 하나로 통일.
- **글꼴(후보, comp 단계에서 측정 후 확정)**: 한글·라틴 겸용 디스플레이 Hahmlet 계열, 본문 Pretendard. 고유명사는 로마자와 짧은 뜻풀이를 함께 표기.
- **ui-ux-pro-max 근거 데이터**: 관광 카테고리 기본값이 하늘색+주황 사진 포털로 나왔다. 이것이 피해야 할 업계 표준(rut)이라는 근거로만 쓰고, "챕터별 CTA가 있는 스크롤 서사" 패턴만 참고한다.

### 첫 화면

- 화면 전체에 목판에 새긴 한양(내사산·성곽·청계천) 플레이트
- 왼쪽 1/3에 헤드라인 **"Seoul, printed for you."**
- 하단에 범례표 띠: 취향 기호 5~7개가 주 조작부, 끝에 단 하나의 행동 버튼 **Print my Seoul**
- 내비게이션은 한 줄, 높이 72px 이하

### 시그니처 인터랙션: "Pull the print"

취향을 고르고 버튼을 누르면 먹 롤러가 목판 위를 지나가고(Higgsfield 영상, 코드 대체본 포함), 한지가 들리며 내 장소만 찍힌 지도가 드러난다. 이어서 코스 경로가 눈금 단위로 차례로 그려진다.

## 3. 정보 구조

| 경로 | 내용 |
|---|---|
| `/` | 목판 히어로 + 범례 취향 선택 + 서비스 흐름 소개(스크롤 서사 3장) |
| `/print` | 취향·조건 입력 4단계: 관심사 → 여행 목적·동행 → 일정·속도 → 이동 선호 |
| `/atlas` | 결과: 나의 지도, 추천 장소(추천 이유 포함), 일자별 코스 첩 |
| `/place/[slug]` | 지도첩의 한 면처럼 구성한 장소 상세 |
| `/about` | 제안 배경, 데이터 출처, 생성 이미지 표기 |
| `/visit/[place]` | 서울 메타버스 3곳: 경복궁·광장시장·한강공원(사이트 안의 사이트). 4-1절 참고 |

- 다국어: `/[locale]` 세그먼트, 영어 기본 + 한국어 토글
- 저장·공유: 취향 상태를 URL에 인코딩해 링크 공유, 최근 결과는 로컬 저장(서버 없음)

## 4. 추천 로직 (클라이언트)

1. **입력**: 관심사(복수), 여행 목적, 동행(혼자/커플/가족/친구), 일수(1~4일), 속도(여유/빡빡), 도보 허용 정도, 방문 계절(날짜에서 자동)
2. **점수**: 장소별 취향 태그 가중 합 + 동행·계절 적합도 − 이미 고른 장소와의 중복 패널티(다양성 확보, MMR 방식)
3. **이유 생성**: 일치한 태그로 "Because you picked Palaces and Slow mornings" 같은 한 줄 이유를 만든다
4. **코스 구성**: 상위 장소를 좌표 기준으로 권역 묶음 → 일자 배정 → 최근접 순서로 정렬 → 운영 시간·소요 시간으로 검증
5. **빈 상태·예외**: 조건이 너무 좁으면 가까운 대안 취향 제안, 운영 정보는 "발표 시점 기준" 표기

로직은 TDD로 작성한다(`test-driven-development`): 점수, 다양성, 권역 묶음, 순서 정렬 각각 단위 테스트.

## 4-1. 서울 메타버스: "Step into the print"

메인 사이트의 지도첩에서 메타버스 장소 기호를 누르면, 찍혀 있던 목판화가 입체 디오라마로 일어서며 3D 공간으로 들어간다. 장소마다 별도의 방이 있고 각 방에는 **동시에 10명까지만** 머문다.

### 장소 3곳

| 장소 | 성격 | 핵심 체험 |
|---|---|---|
| 경복궁 (`/visit/gyeongbokgung`) | 궁궐·유산 | 광화문 → 흥례문 → 근정전 마당(품계석) → 경회루 연못, 수문장 교대 장면, 한복 갈아입기 |
| 광장시장 (`/visit/gwangjang`) | 시장·음식 | 좁은 골목 노점, 빈대떡·김밥 노점에서 음식 받아 들고 다니기, 함께 앉는 평상 |
| 한강공원 (`/visit/hangang`) | 자연·휴식 | 돗자리 피크닉, 편의점 라면, 따릉이 자전거, 해 질 녘 다리 야경 |

각 장소는 3~5분이면 한 바퀴를 도는 크기이고, 안내 지점에 다가가면 지도첩 한 면 모양의 영어 설명(한국어 토글)이 펼쳐진다. 남산서울타워는 한강공원 대신 넣을 수 있는 예비 후보다.

### 표현: 아늑한 장난감 디오라마

- 느낌의 기준: 닌텐도 "동물의 숲" 같은 아늑한 생활 시뮬레이션 장르. 둥글고 통통한 저폴리곤, 큰 머리의 2.5등신 아바타, 밝은 햇살과 부드러운 그림자, 느린 산책 속도, 손바닥만 한 세계
- 장르의 감각만 가져오고 특정 게임의 캐릭터·그림체·UI·아이콘·효과음은 쓰지 않는다. 모든 형태와 캐릭터는 이 프로젝트를 위해 새로 만든다
- 메인 사이트와의 연결: 진입 전환(목판화가 일어서는 장면), 범례 기호를 쓴 UI, 쪽빛 포인트 색은 그대로 쓴다. 3D 세계 자체는 목판 셰이딩 대신 따뜻하고 부드러운 툰 셰이딩으로 바꾼다
- React Three Fiber + drei. 건물은 코드로 만든 둥근 저폴리곤(곡선 지붕, 통통한 기둥), 노점·해태상·자전거 같은 소품은 Higgsfield 3D 생성으로 만든다
- 장소당 3D 자산은 Draco 압축 기준 5MB 이내. 메타버스 경로는 클릭했을 때만 불러온다(메인 사이트 로딩에 영향 없음)
- 아바타: 통통한 인물형, 한복·여행자 옷 몇 가지와 색 선택, 닉네임은 "Magpie 7"처럼 자동 생성(개인정보 수집 없음)

### 조작

- 데스크톱: WASD/방향키 + 마우스 시점, 클릭 지점으로 이동
- 모바일: 가상 조이스틱 + 탭 이동, 안전 영역 처리
- WebGL을 쓸 수 없거나 `prefers-reduced-motion`이면 사진과 텍스트로 구성한 "읽는 경복궁" 페이지로 대체

### 실시간 동기화와 10명 제한 (Supabase Realtime)

| 요소 | 방식 |
|---|---|
| 접속자 파악 | 장소별 Presence 채널(`gyeongbokgung`, `gwangjang`, `hangang`)에 `{id, joinedAt, avatar}` 등록 |
| 10명 제한 | 모든 클라이언트가 같은 규칙으로 `joinedAt` 순 정렬, 1~10번째만 입장. 11번째부터는 대기 상태가 된다. 규칙이 같으므로 모든 화면이 같은 결론을 낸다 |
| 대기열 | "You're 3rd in line" 순번 표시, 누가 나가면 자동 입장. 기다리는 동안 경복궁 소개 영상과 지도첩 콘텐츠를 보여준다 |
| 위치 동기화 | Broadcast로 초당 10회 위치·방향 전송, 받는 쪽은 보간해 부드럽게 표시 |
| 소통 | 다국어 프리셋 문구("Hello!", "Photo here?", "Follow me") 말풍선 + 이모트(인사 절, 손 흔들기, 사진 포즈) |
| 비활성 정리 | 2분간 입력이 없으면 자동 퇴장해 자리 반환 |

**한계와 보완**: 이 방식은 클라이언트끼리 합의하는 구조라 조작된 클라이언트는 제한을 우회할 수 있다. 발표용으로는 충분하며, 실제 운영 단계에서는 입장권을 발급하는 Supabase Edge Function이나 Colyseus 서버로 바꿔 서버가 인원을 강제하도록 한다.

**발표 전 확인**: Supabase 무료 프로젝트는 일정 기간 쓰지 않으면 일시 정지되므로 발표 하루 전에 접속해 깨워 둔다.

## 7. 기술 스택과 라이브러리 (`pick-ui-library` 기준)

| 용도 | 선택 |
|---|---|
| 프레임워크 | Next.js (App Router) + TypeScript, Vercel 배포 |
| 스타일 | Tailwind v4 + CSS 변수 토큰, 클래스 조합은 clsx, 변형 컴포넌트는 cva |
